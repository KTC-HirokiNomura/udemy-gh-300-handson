# L8-1 実践: パブリック コード フィルターとエディターの設定

github.comのCopilotの設定で、パブリック コードに一致する提案の扱いを見ます。VS Codeの設定で、特定の言語の補完を止め、提案が出ないときの確かめ方を見ます。

## 前提

- L0-2 を終えて、Codespacesを開いていること

## 進め方

| 手順 | やること |
|---|---|
| 1 | パブリック コードに一致する提案の設定を見る |
| 2 | 許可とブロックの違いを確かめる |
| 3 | Pythonの補完を止める |
| 4 | 補完が出ないことを確かめ、元に戻す |
| 5 | 提案が出ないときの確かめ方 |

### 1. パブリック コードに一致する提案の設定を見る

1. github.comの右上のアイコン → 「Settings」 → 左の「Copilot」 → 「Features」を開きます
2. 下のほうの「Privacy」の **Suggestions matching public code** を見ます。「Allowed」（許可）か「Blocked」（ブロック）を選べます。ブロックにして一致する提案を出さないようにすることを、パブリック コード フィルターと呼びます

> 組織からCopilotの席を受けている場合は、この設定を個人では変えられず、組織やエンタープライズの設定を受け継ぎます。

### 2. 許可とブロックの違いを確かめる

| 設定 | 提案の扱い |
|---|---|
| 「Blocked」 | 多くの製品で、提案を周りのコードと合わせて公開コードと照らし合わせ、一致や、ほぼ一致する提案を出しません |
| 「Allowed」 | 一致する提案も出します。そのとき、一致したコードの参照（コード参照。ライセンスの種類と、元のファイルのURL）を確かめられます |

VS Codeでは、画面の下の「出力」のパネルを開き、右のメニューで「GitHub Copilot Log (Code References)」を選ぶと、コード参照の記録を見られます。

この教材では設定を変えません。

### 3. Pythonの補完を止める

1. CodespacesでCtrl+,（MacではCmd+,）を押して、設定を開きます。左下の歯車 → 「設定」からも開けます
2. 上の「ユーザー」「リモート [Codespaces: …]」「ワークスペース」のうち、「リモート [Codespaces: …]」を選びます（このCodespaceだけに効きます）
3. 検索欄に `github.copilot.enable` と入れます
4. 「GitHub › Copilot: Enable」の「項目の追加」を押し、項目に `python` と入れます。値は選択式なので、`false` を選んで「OK」を押します
5. 表に `python` と `false` の行が足されたことを確かめます

### 4. 補完が出ないことを確かめ、元に戻す

1. `app/booklib/stats.py` を開き、コメントの下で `def ` と打ちます。灰色の提案が自動では出ないことを確かめます。画面の下のステータス バーにあるCopilotのアイコンを押すと、「インライン候補」が「無効」と出ます
2. 打った文字を消し、設定に戻って、`python` の行の右の × を押して消します。もう一度 `def ` と打つと、提案が出ます

### 5. 提案が出ないときの確かめ方

提案が出ないときは、まず、一部のファイルだけか、どのファイルでも出ないのかを見ます。

- 一部のファイルだけなら、組織の設定で、そのファイルがCopilotの対象から外されていないか（コンテンツ除外。第8章の座学）
- どのファイルでも出ないなら、サインインしているか（左下のアカウントと、ステータス バーのCopilotのアイコン）、この言語の補完を止めていないか（手順3の設定）、ネットワークにつながっているか

## まとめ

- パブリック コードに一致する提案は、個人の設定で許可かブロックを選べます
- `github.copilot.enable` で、言語ごとに、自動で出る補完を止められます
- 提案が出ないときは、一部のファイルだけか、どのファイルでもかを見てから、除外・サインイン・設定・ネットワークを確かめます
