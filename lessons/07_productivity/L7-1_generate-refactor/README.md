# L7-1 実践: 説明・サンプル データ・古いコードの書き直し・ドキュメント

初めて読む古いスクリプト（`legacy/old_report.py`）を、Copilotと一緒に読み、今の書き方に直します。説明を頼み、テスト用のサンプル データを作らせ、書き直し、docstringとREADMEの節を書かせます。最後に、テストが決めている振る舞いが変わっていないことを確かめます。

## 前提

- L0-2 を終えて、Codespacesを開いていること
- L4-2（Chat）と L4-3（エージェント モード）を見ていること
- Chatの答えとエージェントは、AIクレジットを使います

## 進め方

| 手順 | やること |
|---|---|
| 1 | レッスン用のブランチを作り、テストが通ることを確かめる |
| 2 | 知らないコードの説明を頼む |
| 3 | テスト用のサンプル データを作らせる |
| 4 | 古い書き方のコードを、今の書き方に直させる |
| 5 | docstringとREADMEの節を書かせる |
| 6 | テストで確かめる |

### 1. レッスン用のブランチを作り、テストが通ることを確かめる

```bash
git switch main && git switch -c lesson/l7-1
pytest -q tests/test_legacy_report.py
```

`3 passed` と出ます。このテストは、`legacy/old_report.py` の今の振る舞いの一部（読み込む件数と1冊目の中身・報告の1行目と冊数の合計・書き出すファイルの先頭）を決めています。直したあとも、このテストが通ることを目標にします。

### 2. 知らないコードの説明を頼む

1. `legacy/old_report.py` を開きます
2. Ctrl+Alt+IでChatを開き、右上の「＋」（新しいチャット）を押します。入力欄のさらに下の切り替えを「ローカル」に、入力欄の左下のモードを「Ask」にします
3. 次を送ります

```text
このスクリプトは何をしますか？初めて読む人向けに、処理の流れを順に説明してください。古い書き方になっている所も挙げてください。
```

CSVを読み、著者ごとの冊数を数え、`out/report.txt` に書き出す流れが説明されます。古い書き方としては、たとえば `open` と `close` を手で書いている所や、`%` での文字列の組み立てが挙がります（答えは回ごとに変わります）。知らないコードを読むときに、まず全体の流れをつかめます。

### 3. テスト用のサンプル データを作らせる

同じチャットで、次を送ります。

```text
load_books が読む CSV と同じ列で、テスト用のサンプル データを5行作ってください。同じ著者の本を2冊含めてください。ヘッダーの行も付けて、CSV のコード ブロックで出してください。
```

答えのコード ブロックにマウスを置くと、右上にボタンが出ます。「…」→「新しいファイルに挿入する」を選ぶと、名前の無いファイルに入ります。Ctrl+Sで保存し、保存先の欄を `/workspaces/udemy-gh-300-handson/tests/data/sample_books.csv` にします。まだフォルダーが無いので「パスが存在しません」と出ますが、そのままEnterを押します。「フォルダー data が存在しません。作成しますか?」と出たら「OK」を押します。

```bash
python legacy/old_report.py tests/data/sample_books.csv && cat out/report.txt; echo
```

蔵書の数が5で、同じ著者が2冊と数えられていれば、サンプル データとして使えます。

### 4. 古い書き方のコードを、今の書き方に直させる

1. 入力欄の左下のモードを「Agent」にします
2. 次を送ります

```text
legacy/old_report.py を、今の Python の書き方に直してください。関数の名前・引数・戻り値と、書き出す報告の文は変えないでください。with 文、pathlib、csv モジュール、collections.Counter、f 文字列、型ヒントを使ってください。直したら、pytest で tests/test_legacy_report.py を走らせて確かめてください。
```

3. 途中で、テストやコマンドを実行してよいかを聞かれます（「テストの実行を許可しますか?」「bash コマンドを実行しますか?」）。何を実行するかを読んでから許可します。緑のボタンが「このセッションで許可する」のときは、このセッションのあいだ聞かずに許すことになります。今回だけ許すときは、ボタンの右の▾から「一度のみ許可」を選びます
4. 終わったら、エディターの差分で変更を読みます。読んで納得できたら「保持」（Keep）を押します。戻したいときは「元に戻す」を押します

### 5. docstringとREADMEの節を書かせる

同じチャットで、次を送ります。

```text
legacy/old_report.py の各関数に、日本語の docstring を足してください。また、このスクリプトの使い方を、README に載せる短い節として、見出しとコマンドの例で書いてください。README のファイルは変えず、答えの中に出してください。
```

途中で `pytest` の実行を聞かれたら、コマンドを読んでから許可します。終わったら、差分を読んで「保持」を押します。docstringはファイルに入ります。READMEの節は答えの中に出るので、読むだけにします。節の中のコマンドの例が、このリポジトリのファイルの場所（`legacy/`・`data/`）と合っているかも確かめます。

### 6. テストで確かめる

```bash
pytest -q tests/test_legacy_report.py
git diff --stat
```

`3 passed` と出れば、テストが決めている振る舞いは、直す前と同じです。テストの無い振る舞いまでは確かめられていません。差分の大きさも見ておきます。

## 後片付け

```bash
git checkout -- . && rm -rf tests/data out && git switch main && git branch -D lesson/l7-1
```

## まとめ

- 知らないコードは、まず説明を頼んで、全体の流れをつかみます
- サンプル データは、読む側のコードと同じ形で作らせ、実際に読ませて確かめます
- 古いコードを直すときは、振る舞いを決めるテストを先に用意し、直したあとに走らせます。大きな書き直しは、小さな段階に分けると確かめやすくなります
