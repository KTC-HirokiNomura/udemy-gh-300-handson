# L7-2 実践: テスト・エッジ ケース・セキュリティと性能の見直し

Copilotに、単体テストと統合テストを作らせます。エッジ ケースを挙げさせ、アサーションを足します。続いて、入力の検証などのセキュリティの改善と、遅いループの性能の改善を提案させ、テストを走らせてから受け入れるかを決めます。

## 前提

- L0-2 を終えて、Codespacesを開いていること
- L4-2（Chat）と L4-3（エージェント モード）を見ていること
- Chatの答えとエージェントは、AIクレジットを使います

## 進め方

| 手順 | やること |
|---|---|
| 1 | レッスン用のブランチを作る |
| 2 | 単体テストを、エッジ ケースと一緒に作らせる |
| 3 | 統合テストを作らせる |
| 4 | セキュリティの改善を提案させる |
| 5 | 性能の改善を提案させ、テストで確かめてから受け入れる |

### 1. レッスン用のブランチを作る

```bash
git switch main && git switch -c lesson/l7-2
pytest -q
```

今のテストが、すべて通ることを確かめておきます。

### 2. 単体テストを、エッジ ケースと一緒に作らせる

1. `app/booklib/loans.py` を開きます
2. Ctrl+Alt+IでChatを開き、右上の「＋」（新しいチャット）を押します。入力欄のさらに下の切り替えを「ローカル」に、入力欄の左下のモードを「Agent」にします
3. 次を送ります

```text
LoanService.overdue の単体テストを tests/test_loans.py に足してください。先にエッジ ケースを挙げてから、それぞれをアサーションで確かめるテストにしてください。足したら pytest で確かめてください。
```

4. ツールやコマンドの実行の許可を聞かれたら、読んでから「許可」を押します。ファイルを探すコマンドが失敗の印付きで終わることがありますが、エージェントは別の方法で調べ直して進みます
5. 答えに、エッジ ケース（たとえば、返却期限の当日、返却済みの貸出、貸出が無いとき）と、足したテストの結果が出ます。答えは回ごとに変わります。変更を読み、「保持」のボタンが出ていれば、納得してから押します

### 3. 統合テストを作らせる

同じチャットで、次を送ります。

```text
data/books.csv を load_catalog で読み、LoanService で貸し出し、report.format_overdue で延滞の文を作るまでを通して確かめる統合テストを、tests/test_integration.py に作ってください。作ったら pytest で確かめてください。
```

単体テストは1つの関数を、統合テストは複数の部品のつながりを確かめます。変更を読み、納得できたら「保持」を押します。

### 4. セキュリティの改善を提案させる

1. 入力欄の左下のモードを「Ask」にします
2. 入力欄に `#loans` と打ち、候補の一覧から `loans.py` を選びます。続けて次の文を入れて、送ります

```text
の borrow について、入力の検証とセキュリティの観点で問題を挙げ、直す案を出してください。
```

存在しない蔵書IDを貸してしまう、貸出中の本をもう一度貸してしまう、といった、入力を検証していない問題が挙がります。ここでは読むだけにします（コードは変えません）。

### 5. 性能の改善を提案させ、テストで確かめてから受け入れる

1. Askのまま、入力欄に `#catalog` と打ち、候補の一覧から `catalog.py` を選びます。続けて次の文を入れて、送ります

```text
の search の性能の問題と、振る舞いを変えない改善案を出してください。
```

2. キーワードごとに全部の本を回し、結果のリストを毎回探している二重のループが挙がります。改善案（たとえば、見つけた本を集合で覚えておく）を読みます
3. モードを「Agent」にして、次を送ります

```text
いまの改善案で catalog.py の search を直してください。結果の順番と中身は変えないこと。直したら pytest をすべて走らせてください。
```

4. コマンドの実行を聞かれたら、読んでから「許可」を押します。テストがすべて通ったことを確かめ、差分を読んでから「保持」を押します。テストが通っても、テストが確かめていない振る舞いまでは確かめられていません。答えにそう書かれていたら、テストを足すかを考えます

## 後片付け

```bash
git checkout -- . && git clean -fd tests && git switch main && git branch -D lesson/l7-2
```

## まとめ

- テストを頼むときは、エッジ ケースを先に挙げさせ、アサーションで確かめさせます
- 単体テストは1つの部品を、統合テストは部品のつながりを確かめます
- セキュリティや性能の改善案は、そのまま受け入れず、テストを走らせてから決めます
