# L6-3 実践: クラウド エージェントに作業を任せる

リポジトリの「Agents」タブから、Copilotに小さな修正を頼みます。クラウド エージェントがGitHubの上で作業し、PRを作ります。PRを読み、コメントで直しを頼んでから、受け入れるかを決めます。

## 前提

- L0-2 を終えて、Forkしたリポジトリがあること
- クラウド エージェントは、有料プラン（Pro・Pro+・Maxなど）の機能です。AIクレジットと、GitHub Actionsの実行時間を使います（この講座の確認では、1回の作業で約23クレジットを使いました）

## 進め方

| 手順 | やること |
|---|---|
| 1 | 「Agents」タブから作業を頼む |
| 2 | 作業の進みを見る |
| 3 | できたPRを読む |
| 4 | コメントで直しを頼む |
| 5 | マージするかを決める |

### 1. 「Agents」タブから作業を頼む

1. Forkしたリポジトリをgithub.comで開き、上のタブの「Agents」を押します
2. 入力欄の下のブランチが `main` になっていることを確かめます
3. 入力欄に次を貼り付けて、右の送信ボタンを押します

   ```text
   app/booklib/catalog.py の Catalog.find_by_title は、大文字と小文字を区別します。find_by_title("python") でも「Python 入門ノート」が見つかるようにして、PRを作ってください。既存のテスト（pytest）がすべて通ること。大文字と小文字を区別しないことを確かめるテストを tests/test_catalog.py に足すこと。
   ```

何を直すか、どうなれば終わりか（テスト）を、具体的に書きます。「PRを作ってください」と書くと、作業の最後にPRまで作ります。

> 「Agents」タブが無いときや、作業が始まらないときは、github.comの右上のアイコン → 「Settings」 → 「Copilot」 → 「Features」で、「Copilot cloud agent」が有効かを確かめます。

### 2. 作業の進みを見る

送信すると、下の一覧にセッションが1つ足されます。押すと、エージェントが何をしているかのログが出ます。

1. 「Setting up environment」で、リポジトリを取り出し、作業の環境を準備します
2. ファイルを読み、テストとコードを直し、`pytest` を実行します
3. 最後に、自分の変更をCopilotのコード レビューとCodeQLで確かめてから、PRを作ります

数分で終わり、ログの下に「PR #… を作成しました」と、変更の要約が出ます。その下に、使ったモデルとクレジットも出ます。

### 3. できたPRを読む

1. ログの下の「View pull request」を押します。下書き（Draft）のPRが開きます
2. 「Files changed」タブで、変更を読みます。たとえば、`find_by_title` で検索語と書名の両方を `casefold()` してから比べる変更と、`find_by_title("python")` などのテストが足されます

手元でも確かめられます。

```bash
git fetch origin
git switch <PR のブランチ名>
pytest -q
```

### 4. コメントで直しを頼む

直してほしいところがあれば、PRの下のコメント欄に `@copilot` を付けて書き、「Comment」を押します。

```text
@copilot find_by_title の docstring に、大文字と小文字を区別しないことを書いてください。
```

エージェントがもう一度動き、同じPRにコミットを足して、何を直したかをコメントで返します（1〜2分）。

### 5. マージするかを決める

- 変更とテストに納得できたら、「Ready for review」を押してから、マージします
- 納得できなければ、マージせずにPRの下の「Close pull request」で閉じます

## 後片付け（手元でブランチに切り替えた場合）

```bash
git switch main
```

## まとめ

- クラウド エージェントは、頼まれた作業をGitHubの上で進め、PRを作ります
- 頼むときは、何を直すかと、終わりの条件を具体的に書きます
- できたPRは人が読み、コメントで直しを頼み、マージするかを自分で決めます
