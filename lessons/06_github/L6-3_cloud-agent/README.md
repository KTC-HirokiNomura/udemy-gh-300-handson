# L6-3 実践: クラウド エージェントに作業を任せる

リポジトリの「Agents」タブから、Copilotに小さな修正を頼みます。クラウド エージェントがGitHubの上で作業し、頼めばPRまで作ります。PRを読み、コメントで直しを頼んでから、受け入れるかを決めます。

## 前提

- L0-2 を終えて、Forkしたリポジトリがあること
- クラウド エージェントは、有料プラン（Pro・Pro+・Max。Business・Enterpriseは管理者が有効にしたとき）の機能です。AIクレジットを使い、GitHub Actionsの環境で動きます（この講座の撮影では、依頼と、コメントでの直しの2回で、10〜40クレジットほどを使いました）

## 進め方

| 手順 | やること |
|---|---|
| 1 | 「Agents」タブから作業を頼む |
| 2 | 作業の進みを見る |
| 3 | できたPRを読む |
| 4 | コメントで直しを頼む |
| 5 | マージするかを決める |

### 1. 「Agents」タブから作業を頼む

1. Forkしたリポジトリをgithub.comで開き、上のタブの「Agents」を押します
2. 入力欄の下のブランチが `main` になっていることを確かめます
3. 入力欄に次を貼り付けて、右の送信ボタンを押します

   ```text
   app/booklib/catalog.py の Catalog.find_by_title は、大文字と小文字を区別します。find_by_title("python") でも「Python 入門ノート」が見つかるようにして、PRを作ってください。既存のテスト（pytest）がすべて通ること。大文字と小文字を区別しないことを確かめるテストを tests/test_catalog.py に足すこと。
   ```

何を直すか、どうなれば終わりか（テスト）を、具体的に書きます。「PRを作ってください」と書くと、作業の最後にPRまで作ります。

入力欄の中の切り替え（モードやモデル）は、既定のまま触りません。

送信すると、そのセッションの画面に移ります。左の「My sessions」の一覧に、セッションが1つ足されます。

> 「Agents」タブが無いときや、作業が始まらないときは、github.comの右上のアイコン → 「Settings」 → 「Copilot」 → 「Features」で、「Copilot cloud agent」が有効かを確かめます。Forkしたリポジトリでは、「Actions」タブを開き、ワークフローを有効にするボタンが出ていれば押してから、もう一度頼みます。

### 2. 作業の進みを見る

セッションの画面には、エージェントが何をしているかのログが出ます。あとから見るときは、「Agents」タブの一覧から開きます。

1. リポジトリのファイルを読み、テストとコードを直し、`pytest` を実行します
2. 回によっては、自分の変更をCopilotのコード レビューとCodeQLで確かめてから、PRを作ります

作業の途中で、コマンドを実行する前やファイルを書き換える前に、確認のカードが出ることがあります（そのあいだ、一覧のセッションは「Needs attention」になります）。カードのコマンドや変更と、黄色の注意書き（Risk assessment）を読んでから選びます。

- 「Run command」のカード: 「Allow」で実行を許し、「Deny」で断ります
- ファイルの変更（「Edit …」）のカード: 「Approve once」で今回だけ許し、「Approve for this session」でこのセッションのあいだは聞かずに許し、「Deny」で断ります

頼んでいないファイルの変更が含まれることもあります。中身を読んで、許すかを決めます（この講座の撮影では、設計のドキュメントの検索の説明を、今の動きに合わせる1行でした。「Approve once」で許しました）。

数分で、ログに、PRを作ったことと、変更の要約が出ます（文は回ごとに変わります）。

PRができたあとも、ログに「Copilot is working…」と出続けることがあります。PRはできているので、次の手順に進んでかまいません。

### 3. できたPRを読む

1. ログの下の「View PR #番号」（または「View pull request」）を押します。下書き（Draft）のPRが開きます。作業のブランチの名前は、Copilotが付けます
2. 「Files changed」タブで、変更を読みます。たとえば、`find_by_title` で検索語と書名の両方を `casefold()` してから比べる変更と、`find_by_title("python")` などのテストが足されます

手元でも確かめられます。

```bash
git fetch origin
git switch <PR のブランチ名>
pytest -q
```

### 4. コメントで直しを頼む

直してほしいところがあれば、PRの下のコメント欄に `@copilot` を付けて書きます。このレッスンでは、`@copilot` をコメントの頭に書きます。ボタンが「Start new session」に変わるので、押します。

ここでは、最初のPRで直った `find_by_title` に続けて、キーワードで探す `Catalog.search` も同じにするよう頼みます。

```text
@copilot Catalog.search も、大文字と小文字を区別しないようにしてください。確かめるテストも足してください。
```

コメントに目のリアクションが付き、エージェントがもう一度動きます。同じPRにコミットを足して、何を直したかをコメントで返します（数分）。終わると、あなたにレビューを頼むことがあります（マージの欄に「Review requested」）。

### 5. マージするかを決める

- 変更とテストに納得できたら、「Ready for review」を押して下書きを外してから、マージします
- このレッスンでは、マージせずに、PRの下の「Close pull request」で閉じます（後のレッスンを、元のコードのまま進めるため）。閉じたあとに出る「Delete branch」を押すと、Copilotの作業ブランチも消せます（あとから「Restore branch」で戻せます）

## 後片付け（手元でブランチに切り替えた場合）

```bash
git switch main
```

## まとめ

- クラウド エージェントは、頼まれた作業をGitHubの上で進め、頼めばPRまで作ります
- 頼むときは、何を直すかと、終わりの条件を具体的に書きます
- できたPRは人が読み、コメントで直しを頼み、マージするかを自分で決めます
