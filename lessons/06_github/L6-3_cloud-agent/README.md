# L6-3 実践: クラウド エージェントにIssueを任せる

小さなIssueを作り、Copilotに割り当てます。クラウド エージェントがGitHubの上で作業し、PRを作ります。PRを読んで、受け入れるかを決めます。

## 前提

- L0-2 を終えて、Forkしたリポジトリがあること
- クラウド エージェントは、有料プランの機能です。AIクレジットと、GitHub Actionsの実行時間を使います

## 進め方

| 手順 | やること |
|---|---|
| 1 | Issueを作る |
| 2 | Copilotに割り当てる |
| 3 | 作業の進みを見る |
| 4 | できたPRを読む |
| 5 | コメントで直しを頼む |
| 6 | マージするかを決める |

### 1. Issueを作る

1. Forkしたリポジトリの「Issues」タブを開きます
   - 「Issues」タブが無いときは、「Settings」 → 「General」 → 「Features」の「Issues」にチェックを入れます
2. 「New issue」を押し、次の題と本文で作ります

題の欄には、次の文を入れます。

```text
タイトル検索で大文字と小文字を区別しない
```

本文の欄には、次の文を入れます。

```text
app/booklib/catalog.py の Catalog.find_by_title は、大文字と小文字を区別します。find_by_title("python") でも「Python 入門ノート」が見つかるようにしてください。

- 既存のテスト（pytest）がすべて通ること
- 大文字と小文字を区別しないことを確かめるテストを tests/test_catalog.py に足すこと
```

何を直すか、どうなれば終わりか（テスト）を、具体的に書きます。

### 2. Copilotに割り当てる

Issueの右側の「Assignees」で「Copilot」を選びます。

### 3. 作業の進みを見る

1. しばらくすると、Copilotが作った下書きのPRが、Issueに結び付いて出ます（題の先頭に `[WIP]`）
2. PRの「View session」から、エージェントが何を読み、何を実行しているかのログを見られます

2〜3分で作業が終わり、PRの題と説明が書き換わります。

### 4. できたPRを読む

「Files changed」タブで、変更を読みます。たとえば、`find_by_title` で検索語と書名の両方を `casefold()` してから比べる変更と、`find_by_title("python")` のテストが足されます。

手元でも確かめられます。

```bash
git fetch origin
git switch <PR のブランチ名>
pytest -q
```

### 5. コメントで直しを頼む

直してほしいところがあれば、PRのコメントに `@copilot` を付けて書きます。

```text
@copilot find_by_title の docstring に、大文字と小文字を区別しないことを書いてください。
```

エージェントがもう一度動き、同じPRにコミットを足します。

### 6. マージするかを決める

- 変更とテストに納得できたら、「Ready for review」を押してから、マージします
- 納得できなければ、マージせずにPRを閉じます

## まとめ

- クラウド エージェントは、Issueを受け取り、GitHubの上で作業してPRを作ります
- Issueには、何を直すかと、終わりの条件を具体的に書きます
- できたPRは、人が読んで、マージするかを決めます
