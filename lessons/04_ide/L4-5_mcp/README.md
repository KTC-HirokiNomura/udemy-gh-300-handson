# L4-5 実践: MCPでツールをつなぐ

GitHub MCPサーバーを、VS CodeのCopilotに追加します。エージェントから、ForkしたリポジトリのIssueを一覧にし、コメントを書いてもらいます。ツールを呼ぶ前の確認の画面も見ます。

## 前提

- L0-2 を終えて、Codespacesを開いていること
- GitHub MCPサーバーを使うには、GitHubでの認可（サインイン）が要ります。手順3で行います
- エージェントは何手順も動くので、AIクレジットを使います（答えの下に、使ったクレジットが出ます）

> 組織からCopilotを受けている場合は、組織のポリシーでMCPが止められていることがあります。組織の管理者が決めます。

## 進め方

| 手順 | やること |
|---|---|
| 1 | 確かめ用のIssueを2つ作る |
| 2 | GitHub MCPサーバーを追加する |
| 3 | サーバーを起動して、GitHubで認可する |
| 4 | ツールの一覧を見る |
| 5 | エージェントにIssueの一覧を頼む |
| 6 | コメントを頼み、ツールの実行を確認する |

### 1. 確かめ用のIssueを2つ作る

1. Forkしたリポジトリをgithub.comで開き、上のタブの「Issues」を押します
2. 「New issue」を押し、次のタイトルと本文で「Create」を押します

   | タイトル | 本文 |
   |---|---|
   | 貸出中の本を貸し出せてしまう | 設計メモ（docs/design.md）では、貸出中の本は貸さない決まりです。LoanService.borrow は、この決まりを確かめていません。 |
   | 延滞の一覧を、返却予定日の古い順に並べる | report.format_overdue の一覧は、貸出の順に並んでいます。返却予定日の古い順に並べると、急ぐものから読めます。 |

3. もう1つも同じように作ります

> 「Issues」のタブが無いときは、L0-2 の手順1を見て、Issuesを有効にします。

### 2. GitHub MCPサーバーを追加する

1. CodespacesでCtrl+Shift+Pを押し、`MCP: サーバーの追加` を選びます
2. サーバーの種類は「HTTP (HTTP またはサーバー送信イベント)」を選びます
3. URLに次を入れて、Enterを押します

   ```text
   https://api.githubcopilot.com/mcp/
   ```

4. サーバーIDに `github` と入れて、Enterを押します
5. 保存先は「グローバル」 → 「Copilot Global」を選びます

`~/.copilot/mcp-config.json` が開き、次の内容が書かれます。このファイルは、Copilot CLI（第5章）と同じ設定ファイルです。

```json
{
    "mcpServers": {
        "github": {
            "type": "http",
            "url": "https://api.githubcopilot.com/mcp/",
            "tools": [
                "*"
            ]
        }
    }
}
```

### 3. サーバーを起動して、GitHubで認可する

追加しただけでは、サーバーは止まったままです。先に起動します。

1. Ctrl+Shift+Pを押し、`MCP: サーバーの一覧表示` を選びます
2. 「ローカルに構成されたサーバーを表示...」 → 「github」 → 「サーバーの起動」を選びます
3. 「MCP サーバー github を信頼して実行しますか?」と出たら、「信頼する」を押します
4. 「MCP サーバー定義 'github' が、GitHub に認証しようとしています。」と出たら、「許可」を押します
5. ブラウザーのタブにGitHubの認可の画面が開きます。求められる権限を読んでから、緑の「Authorize Visual-Studio-Code」を押します
6. VS Codeに戻ると、右下に「github.com にサインインしています...」と出ます。消えるまで待ちます

出力パネルの「MCP: github」に「Discovered 49 tools」のように出たら、つながっています（ツールの数は変わることがあります）。

> 右下の通知の「キャンセル」を押すと、サインインが取り消されます。出力に「401 … missing required Authorization header」と出たら、手順3の1からやり直します。

### 4. ツールの一覧を見る

1. Chatで新しいチャットを開き、入力欄の下の切り替えを「ローカル」に、モードを「Agent」にします
2. 入力欄の下の、ツールのアイコン（ツールの構成）を押します
3. 「GitHub MCP Server」の行を開くと、`list_issues`（Issueの一覧）や `add_issue_comment`（Issueへのコメント）などのツールが並んでいます
4. 確かめたら、Escで閉じます（チェックは変えません）

MCPサーバーを足すと、エージェントが使えるツールが増えます。

### 5. エージェントにIssueの一覧を頼む

次を送ります。

```text
このリポジトリの、開いている Issue を一覧にしてください。番号・タイトル・1行の要約を表で。
```

途中で「bashコマンドを実行しますか?」と `git remote get-url origin` が出たら、読んでから「許可」を押します（どのリポジトリかを確かめるコマンドです）。

「List issues を実行しました – github (MCP サーバー)」と出て、手順1で作った2つのIssueが表になります。この行を押すと、ツールに渡した「入力」と、返ってきた「出力」を見られます。

> Issueの一覧のような、読むだけのツールは、確認なしで動くことがあります。

### 6. コメントを頼み、ツールの実行を確認する

次を送ります。`#2` は、手順5の表にある「延滞の一覧を、返却予定日の古い順に並べる」の番号に変えます。

```text
Issue #2 に「次の版で対応します。」とコメントしてください。
```

コメントを書く前に、「Add comment to issue or pull request を実行する – github (MCP サーバー)」という確認が出ます。

- 「入力」に、どのリポジトリの、どのIssueに、何を書くかが出ます。読んでから選びます
- 「このセッションで許可する」の横の ▾ を押すと、許可する範囲を選べます

| 選択肢 | 意味 |
|---|---|
| 一度のみ許可 | 今回だけ実行する |
| このセッションで許可する | このチャットの間は、同じツールを確かめずに実行する |
| このワークスペースで許可する／常に許可 | このリポジトリで、またはいつでも、確かめずに実行する |
| スキップ | 実行しない |

▾ の下の段では、GitHub MCP Serverのツールをまとめて許可することもできます。

ここでは「一度のみ許可」を選びます。github.comでIssueを開くと、コメントが付いています。

> GitHubの上のもの（Issue・PR・ファイル）を変えるツールは、何をするかを読んでから許可します。

## まとめ

- MCPは、Copilotに外部のツールとデータをつなぐ仕組みです
- GitHub MCPサーバーを足すと、エージェントがIssueやPRを読み書きできるようになります
- GitHubの上のものを変えるツールは、実行の前に確認が出ます。入力を読んでから許可します
